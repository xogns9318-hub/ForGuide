# 모델 카드

## 한 줄 요약

금융상품 추천(대출 / 계좌 / 보험): 자격 규칙으로 거른 상품을 적합도 점수로 정렬하고, 점수에 기여한 항목을 근거로 보여 준다.

모델: 쌍대 비교 라벨로 가중치를 학습하는 LogisticRegression. 기준선은 규칙 가중합 점수다. 세 상품군이 같은 엔진을 쓰고, 상품군마다 피처·필터·가중치 설정만 다르다.

공통 상태 화면 초안:
로딩·빈 결과·실패·재시도·입력 검증·예시 표시·마스킹.

커뮤니티 목록 UI 초안:
서버와 로그인 연결 전에는 예시 게시글을 보여 주며, 모델을 사용하지 않는다.

## 문제 유형

추천. 1단계 자격 규칙 필터, 2단계 적합도 점수 순위.

실제 가입·승인 기록(정답 데이터)이 없으므로 승인 확률은 출력하지 않는다.

### 상품군과 진행 순서

| 순서 | 상품군 | 화면 | 상품 데이터 | 상태 |
| --- | --- | --- | --- | --- |
| 1 | 계좌 | `/service/account` | 금융상품한눈에 정기예금·적금 | 데이터 확보, 진행 중 |
| 2 | 보험 (실손의료보험) | `/service/insurance` | 실손보험정보 API | 데이터 확보, 외국인 조건 없음 |
| 3 | 대출 | `/service/loan` | 금융상품한눈에 개인신용·전세자금대출 | 외국인 조건 조사 필요 |

- 카드(신용·체크)는 추천 대상에서 제외한다. 외국인 가입 조건을 담은 공식 데이터를 확보하기 어렵다.
- 공통 엔진(수집 → 정제 → 자격 필터 → 점수 → 근거)을 계좌로 먼저 완성하고 보험·대출로 확장한다.

### 공통 엔진과 상품군 설정

| 공통 엔진 | 상품군 설정 |
| --- | --- |
| 수집·정제 파이프라인 틀 | 수집할 API, 정제 규칙 |
| 공통 입력: 체류자격, 사이트 언어 | 상품군별 입력 (모드별 질문 표 참고) |
| 자격 필터 (부합 / 확인 필요 / 불일치) | 필터 조건 목록 |
| 점수 `w · 피처`, 근거 문구 생성 | 피처 정의, 가중치 |
| 모드 판정, 결과 그룹·흐림 처리, 출력 형식 | - |
| 평가 (부적격 추천률, 기준선 비교) | 평가용 데이터 |

### 추천 모드 (모두 P1, 정밀 추천은 P2)

| 모드 | 조건 | 비고 |
| --- | --- | --- |
| fast (빠른) | 필수 질문 3개 답변 | 지금 개발한다. |
| plus (기본) | `더 정확한 추천`으로 펼친 질문까지 답변 | 같은 페이지에서 추가 질문을 표시한다(새로고침 없음). 지금은 가채점만 하고 개발은 미룬다. |

- 모드는 펼침 여부, 필수 질문 수, 답변 수로 판정하고 백엔드에서 다시 검증한다.
- 펼친 질문에 답하기 어려우면 다시 접어서 fast 모드로 추천받는다.

## 입력 (X)

### 모드별 질문

| 상품군 | 관문 | fast | plus (추가) |
| --- | --- | --- | --- |
| 계좌 | 본인 명의 통장 여부 | 체류자격, 목적, 방문 가능 여부 | 남은 체류기간, 거주 지역 |
| 보험 (실손) | 건강보험 가입 여부 | 체류자격, 나이, 성별 | 온라인 가입 선호, 보장 범위 |
| 대출 | - | 체류자격, 용도, 희망 금액 | 남은 체류기간, 월소득, 희망 기간 |

- 관문은 추천 질문 전에 묻는 필터이며 fast 질문 수에 넣지 않는다.

**계좌 추천 흐름**

```
본인 명의 통장이 있나요?
  ├ 예     → 예·적금 비교 (추천)
  └ 아니오 → 첫 통장 안내
```

- 첫 통장 안내는 필요한 서류, 개설 순서, 한도제한계좌와 해제 방법, 급여·공과금·휴대폰 요금 연결을 다룬다. 모델이 아닌 고정 안내다.
- 입출금통장은 비교할 공시 데이터가 없고, 금리 차이가 작아 점수로 순위를 매기기 어렵다. 그래서 추천 모델에 넣지 않는다.

### 사용자 입력

| 항목 | 타입 | 예시 | 입력 위치 |
| --- | --- | --- | --- |
| 체류자격 | 선택: 비전문취업(E-9), 방문취업(H-2), 전문인력, 유학생, 재외동포(F-4), 영주(F-5), 결혼이민(F-6), 기타 (번호는 받지 않음) | 비전문취업(E-9) (예시값) | 공통, fast |
| 사이트 언어 | 자동 (언어 설정) | ko | 헤더 |
| 본인 명의 통장 여부 | 선택: 예 / 아니오 | 예 (예시값) | 계좌 관문 |
| 목적 | 선택: 목돈 굴리기(예금) / 모으기(적금) | 예금 (예시값) | 계좌 fast |
| 방문 가능 여부 | 선택: 상관없음 / 원치 않음 | 상관없음 (예시값) | 계좌 fast |
| 건강보험 가입 여부 | 선택: 예 / 아니오 / 모름 | 예 (예시값) | 보험 관문 |
| 나이 | 미정 (숫자 입력 또는 연령대) | 미정 | 보험 fast |
| 성별 | 선택: 남 / 여 | 미정 | 보험 fast |
| 용도 | 선택 (목록 미정) | 생활비 (예시값) | 대출 fast |
| 희망 금액 | 숫자 (단위·범위 미정) | 500만 원 (예시값) | 대출 fast |
| 남은 체류기간 | 구간 선택 (경계 미정), 모름 허용 | 미정 | 계좌·대출 plus |
| 월소득 | 구간 선택 (MDIS 5구간에 맞출지 미정) | 미정 | 대출 plus |
| 거주 지역 | 선택: 시·도 | 경기 (예시값) | 계좌 plus |
| 온라인 가입 선호 | 선택: 예 / 상관없음 | 상관없음 (예시값) | 보험 plus |
| 보장 범위 | 선택: 기본형만 / 비급여까지 | 비급여까지 (예시값) | 보험 plus |
| 희망 기간 | 선택 (개월) | 미정 | 대출 plus |

- 체류자격 선택지는 MDIS 이민자체류실태조사의 체류자격 그룹을 기준으로 한다. "한국국적 취득"은 서비스 대상이 아니어서 선택지에서 뺀다.
- 직업은 받지 않는다. 보험료 데이터에 직업 구분이 없고, 체류자격으로 어느 정도 추려진다.

### 상품 입력: 계좌 (금융상품한눈에 정기예금·적금)

| 항목 | API 필드 | 정제 |
| --- | --- | --- |
| 외국인 가입 | `join_member` (문장) | 가능 명시 / 불가 명시 / 언급 없음 → 부합 / 불일치 / 확인 필요 |
| 가입 제한 | `join_deny` | 1 제한없음, 2 서민전용, 3 일부제한 |
| 신청 방법 | `join_way` | 방문 필요 여부 (영업점만 가능하면 1) |
| 기본 금리 | `intr_rate` (옵션) | 숫자 |
| 최고 우대금리 | `intr_rate2` (옵션) | 숫자, 정밀(P2)에서 사용 |
| 저축 기간 | `save_trm` (옵션) | 개월 |
| 우대조건 | `spcl_cnd` (문장) | 정밀(P2)에서 사용 |
| 기준월 | `dcls_month` | 출처 표시 |

- 2026-10-14 수집 기준, 저축은행 예·적금 중 40개가 거주 외국인 가입 가능("비거주 외국인 외 제한없음", "내·외국인 대상"), 20개가 내국인만 가입을 명시한다. 은행 상품은 외국인 언급이 없다.
- "실명의 개인"은 외국인 가능 여부가 불분명하므로 확인 필요로 둔다.

### 보험 추천 범위

| 구분 | 보험 | 처리 |
| --- | --- | --- |
| 추천 (모델 대상) | 실손의료보험 | 공통 엔진으로 비교 |
| 상황별 안내 | 유학생·외국인 체류보험, 암·뇌·심장 진단비, 상해·후유장해, 정기·종신 등 사망보장, 운전자, 전세보증금반환보증, 주택화재·일상생활배상책임, 치아, 치매·간병, 여행, 펫 | 추천 화면의 고정 안내 문구 (모델 아님) |
| 추천 탭에서 다루지 않음 | 가입 의무가 있는 보험(귀국비용보험·신탁, 외국인근로자 전용 상해보험, 출국만기보험·보증보험), 저축·연금보험, 건강보험료 체납 | 다른 탭에서 안내 |

**실손 추천 흐름**

```
건강보험에 가입돼 있나요?
  ├ 예          → 실손 비교 (추천)
  └ 아니오, 모름 → 상담 탭으로 자동 연결
```

- 실손 추천은 "같은 보장 중에서, 가입하기 편한 곳 가운데 보험료가 낮은 순"으로 정렬한다.
- 건강보험 가입 여부는 점수 피처가 아니라 필터다.
- fast는 보장 범위를 묻지 않으므로 기본형 + 특약1 + 특약2 합계 보험료로 비교한다.
- 5세대 실손의 담보 구성은 모든 보험사가 같다(기본형: 상해급여·질병급여 / 특약1: 3대비급여·상해비급여·질병비급여 / 특약2: 비급여 자기공명영상진단·상해비급여·질병비급여). 그래서 보험료로 비교할 수 있다.
- 다이렉트(온라인) 상품에 자동 가점을 주지 않는다. 외국인은 본인 명의 휴대폰 인증이 필요해 온라인 가입이 항상 편하지 않다. plus에서 온라인 가입 선호가 "예"일 때만 다이렉트 상품을 앞에 두고 인증 안내를 붙인다.
- 실손 상품의 외국인 가입 여부는 기본값을 확인 필요로 둔다. 보험사마다 체류자격·체류기간·건강보험 이용 여부 등으로 추가 심사한다.
- 병력은 묻지 않는다.

### 상품 입력: 보험·대출

- 보험: 실손보험정보 API의 보험사, 상품명, 유형(일반 / 유병력자 / 노후), 담보, 가입 연령, 남녀 보험료. 보험사마다 기준일이 달라 보험사별 최신 기준일을 고른다. 담보명의 띄어쓰기가 섞여 있어 정제가 필요하다.
  - 2026-10-15 수집 기준 18개 보험사(생명보험 7, 손해보험 11), 최신 상품 33개.
  - MG손보는 비교에서 제외한다. 최신 기준일이 2025-01이고 4세대 상품뿐이라 5세대와 담보 구성이 다르다.
  - 손해보험사의 5세대 상품 행에 노후·유병력자 담보가 섞여 있어, 상품 유형에 맞는 담보만 남긴다.
- 대출: 금융상품한눈에 개인신용대출(한도 필드 없음, 신용점수 구간별 금리)과 전세자금대출(한도는 문장). 가입 대상 필드가 없어 외국인 조건을 따로 조사한다.

### 자격 규칙 필터

- 외국인 가입 불가 명시
- 체류자격 불가
- 상품 기간이 남은 체류기간보다 김
- 운영 종료 상품
- 대출: 용도 불일치

### 점수 피처

| 피처 | 계산 | 상품군 | fast | plus |
| --- | --- | --- | --- | --- |
| 금리 | 기본 금리 | 공통 | O | O |
| 확인 필요 개수 | 판정하지 못한 자격 조건 수 | 공통 | O | O |
| 방문 필요 여부 | 0 / 1 | 공통 | O | O |
| 기간 일치 | 저축 기간과 남은 체류기간의 관계 (계산식 미정) | 계좌 | X | O |
| 한도 충분도 | min(한도 ÷ 희망 금액, 1) | 대출 | O | O |
| 총 상환 비용 | 희망 금액·기간·기본 금리·상환방법 (우대금리 제외) | 대출 | X | O |
| 상환 부담 | 월 상환액 ÷ 월소득 | 대출 | X | O |

### 계좌 채점 기준표 (기준선)

예·적금은 금리가 **높을수록** 좋다(대출과 반대). 대출에서 정한 원칙처럼 표시 금리만 보지 않는다.

**자격 판정**

| 조건 | 판정 |
| --- | --- |
| 가입대상에 내국인만 명시 | 불일치 (흐림) |
| 방문 원치 않음 + 영업점에서만 가입 | 불일치 (흐림) |
| 저축 기간이 남은 체류기간보다 김 | 불일치 (흐림). 체류 중 중도 해지하면 약정 금리를 받지 못한다 |
| 가입대상에 외국인 언급 없음 ("실명의 개인", "제한없음" 등) | 확인 필요 +1 |
| 남은 체류기간 모름 | 확인 필요 +1 |
| 거주 외국인 가입 가능 명시 | 부합 |

**점수 (부합·확인 필요 그룹 안에서 정렬)**

```
점수 = 0.5 × 금리점수 − 0.3 × 확인 필요 개수 − 0.2 × 방문 필요
```

- 가중치는 사람이 정한 출발점이며, 쌍대 비교로 학습한 가중치와 비교한다.
- 금리점수는 기본 금리만 쓴다. 최고 우대금리(`intr_rate2`)와 우대조건은 정밀 추천(P2)에서 다룬다.
- 기본 금리를 단리·복리에 따라 **연 환산 실제 수익률**로 바꾼다.
  - 단리(S): 연 금리 그대로
  - 복리(M): `((1 + 연 금리/12)^개월수 − 1) ÷ (개월수/12)`. API에 복리 주기가 없어 월복리로 가정한다(확인 필요).
- 금리점수 = `1 − (후보 중 최고 실제 수익률 − 이 상품 실제 수익률) ÷ 1.0%p`, 0~1로 자른다. 최고보다 1%p 낮으면 0점이다.
- 후보는 같은 사용자에게 같은 그룹(부합 / 확인 필요)으로 판정된 상품 중 같은 목적(예금/적금)·같은 비교 기간의 상품이다. 최고 수익률은 그룹 안에서 잡는다. 사용자는 그룹 단위로 결과를 보고, 확인 필요 그룹의 고금리 상품이 부합 상품의 점수를 낮추지 않게 하기 위해서다.
- 점수가 같으면 실제 수익률이 높은 순으로 정렬한다.
- 예금은 원금이 달라도 같은 기간·같은 금리 방식이면 순위가 같으므로 금액을 묻지 않는다. 세금도 순위에 영향이 없어 뺀다.
- 적금은 매달 넣는 방식이라 실제 이자 계산이 예금과 다르다. 예금과 적금은 목적으로 나뉘어 서로 비교하지 않는다.

**비교 기간**

| 모드 | 기준 |
| --- | --- |
| fast | 남은 체류기간을 묻지 않으므로 체류자격으로 정한다. 영주(F-5)·결혼이민(F-6)은 12개월, 그 밖은 6개월. 이 경우 기간을 확인 필요로 세지 않는다. |
| plus | 남은 체류기간 안에 끝나는 가장 긴 기간 |

## 결과 근거

점수에 기여가 큰 피처 2~3개를 정해진 문구 템플릿으로 표시한다. 문구는 사이트 언어로 보여 준다.

기여도는 `가중치 × 피처값`으로 계산한다. 선형 모델이라 추천마다 근거를 따로 계산할 수 있다.

요청마다 LLM으로 설명을 생성하지 않는다(응답 시간, 비용, 환각 위험).

## 모델과 학습 방법

### 왜 이 방식인가

- 실제 가입·승인 기록이 없어서 "이 사람에게 맞는 상품"을 정답으로 학습할 수 없다.
- 사람에게 "이 상품은 몇 점인가"를 물으면 기준이 들쭉날쭉하지만, "이 사용자에게 A와 B 중 어느 쪽이 나은가"는 일관되게 답할 수 있다.
- 그래서 정답을 **쌍대 비교**로 만든다. 라벨이 규칙이 아니라 사람의 판단에서 나오므로, 규칙을 그대로 외우는 라벨 순환을 피한다.

### 학습

1. 가상 사용자 1명과 자격 필터를 통과한 상품 2개를 짝지어 비교 쌍을 만든다.
2. 입력은 두 상품의 피처 차이(`A − B`), 정답은 "A가 낫다 = 1"로 LogisticRegression을 학습한다.
3. 학습된 계수 `w`가 곧 각 피처의 가중치다.

### 라벨 만들기 (혼합 방식)

사람의 비교 판정을 수백 개 만들 시간이 없으므로 아래를 섞는다.

| 방식 | 대상 | 배우는 것 |
| --- | --- | --- |
| 자동 라벨 | 모든 피처에서 한쪽이 같거나 나은 쌍 | 피처의 방향 (예: 금리는 낮을수록 좋다) |
| 사람 판정 | 무언가를 포기해야 하는 쌍, 그중 기준선 점수가 비슷한 쌍 우선 | 피처 사이의 중요도 크기 |
| 팀 분담 | 사람 판정을 팀원과 나눔 | 한 사람의 기준에 치우치지 않게 함 |

- 사람 판정 쌍의 일부는 평가용으로 떼어 두고 학습에 쓰지 않는다.

**가상 사용자** (`ai/preprocessing/build_virtual_users.py`)

- MDIS 2025 공통항목의 외국인 응답자(한국국적 취득 제외)에서 가중값에 비례해 60명을 뽑는다. 체류자격·월소득·연령대·성별을 그대로 가져온다.
- 체류자격마다 최소 5명을 먼저 뽑는다. 인원이 적은 체류자격도 비교 쌍에 들어가게 하기 위해서다.
- 평가할 때는 체류자격별 `현실 비율 ÷ 표본 비율`을 가중치로 곱해 현실 분포 기준으로 되돌린다.
- MDIS에 없는 값(계좌 목적, 방문 가능 여부, 대출 용도)은 선택지 중 고르게 무작위로 붙인다. 관문을 통과한 사용자만 모델로 오므로 건강보험·본인 명의 통장은 모두 "예"로 둔다.
- 라벨이 부족해 모델이 기준선을 넘지 못하면 기준선을 서비스에 쓰고, 모델은 실험 결과로 보고한다.

### 서비스에서의 사용

- 상품마다 `w · 피처`를 한 번씩 계산해 정렬한다. 쌍마다 비교(토너먼트)하지 않는다.
- 요청마다 학습하지 않는다. 학습은 오프라인에서 하고, 서비스는 가중치만 쓴다.
- 상품 데이터는 미리 수집·적재해 두고, 요청 중에는 공공 API를 호출하지 않는다.
- 계산하지 못한 피처는 0이나 충족으로 바꾸지 않고 '확인 필요'로 처리한다.

### 피처 설계 원칙

- 원래 값(금리, 한도)을 그대로 넣으면 "금리 낮고 한도 높은 순" 정렬과 같아진다. 그래서 **사용자 기준의 관계 값**으로 만든다. 예: 한도 ÷ 희망 금액, 월 상환액 ÷ 월소득.
- 학습 때 보지 못한 범위의 값은 상한·하한으로 자른다.
- 국적은 피처로 쓰지 않는다. 상품 조건에 실제로 쓰이는 값(체류자격, 남은 체류기간, 소득)만 쓴다.

### 쓰지 않는 것

| 모델 | 이유 |
| --- | --- |
| Keras MLP | 학습 데이터가 적고, 추천별 근거를 설명할 수 없다. |
| RandomForest, GradientBoosting | 전체 피처 중요도만 알 수 있고 추천별 근거가 약하다. 성능 비교용으로만 고려한다. |
| KMeans | 점수를 내지 않는다. 사용자 유형별 가중치가 필요해지면 보조로 검토한다. |
| 승인 확률 모델 | 신용·승인 데이터 없이 만든 확률은 근거 없는 정밀도가 된다. |

## 공통 상태 화면

헤더·푸터 없이 공통 배경의 중앙에 아이콘과 문구를 표시한다.

- 로딩: 회전하는 모래시계와 대기 문구
- 빈 결과: 빈 목록 안내
- 실패·재시도: X 표시, 실패 안내와 재시도 버튼
- 입력 검증: 입력 항목 아래 오류 표시
- 예시 표시: 예시 데이터·예시값 배지
- 마스킹: 가상 이름·계좌번호를 일부 가려 표시
- 잘못된 접근: X 표시와 오류 문구

입력 검증 화면은 필수 입력을 확인하는 표시 초안이다.
실제 서비스 입력 항목과 검증 범위는 미정이다.

## 회원가입 화면 (`/signup`)

모델 화면은 아니며, 인증 흐름의 첫 화면이다. 경로·입력 항목은 Figma "회원가입 · 입력", 화면 구성은 팀 공통 규격(Banner + panel + form-grid) 기준. 현재 실제 인증 API로 동작한다 ("예시 데이터" 배지는 화면 코드 리뷰 때 정리).

| 항목 | 타입 | 범위 | 입력 위치 |
| --- | --- | --- | --- |
| 아이디 | 문자열 | 4~20자, 영문 소문자·숫자, 입력칸을 벗어나면 자동 중복 확인 | `/signup` |
| 비밀번호 | 문자열 | 8~32자, 소문자·대문자·숫자·특수문자 모두 포함, 보기 버튼 | `/signup` |
| 이름 | 문자열 | 1~50자, 문자 종류 제한 없음 | `/signup` |
| 이메일 | 문자열 | 이메일 형식, 중복 불가 | `/signup` |

결과: 가입 성공 시 로그인 화면(`/login`)으로 이동한다. 입력 오류·중복은 해당 입력칸 아래에, 네트워크 등 그 밖의 실패는 폼 아래에 표시한다.

## 로그인 화면 (`/login?next=`)

모델 화면은 아니다. 경로·입력 항목은 Figma "로그인 · 마이페이지로 이동", 화면 구성은 팀 공통 규격 기준. 현재 실제 인증 API로 동작한다 ("예시 데이터" 배지는 화면 코드 리뷰 때 정리).

| 항목 | 타입 | 범위 | 입력 위치 |
| --- | --- | --- | --- |
| 아이디 | 문자열 | 빈 값만 확인 (가입 규칙을 드러내지 않음) | `/login` |
| 비밀번호 | 문자열 | 빈 값만 확인, 보기 버튼 | `/login` |
| next | 쿼리 | 내부 경로만 허용, 외부 주소·로그인·회원가입 화면이면 홈(`/`) | 주소 |

결과: 성공하면 `next` 화면(없으면 홈)으로 이동한다. 실패하면 아이디·비밀번호 중 무엇이 틀렸는지 구분하지 않고 안내하며 비밀번호 칸을 비운다. 회원가입 직후에는 가입한 아이디를 미리 채운다. 이미 로그인한 상태로 들어오면 바로 `next`로 이동한다.

회원 전용 화면(`/mypage`, `/mypage/edit`)은 `RequireAuth`로 감싼다. 로그인 복원 중에는 확인 중 안내를 보여 주고, 로그인하지 않았으면 `/login?next=원래주소`로 보낸다. 화면 보호일 뿐이며 회원 정보는 서버가 토큰으로 다시 확인한다.

## 마이페이지 (`/mypage`)

모델 화면은 아니다. 로그인 필요(`RequireAuth`). 화면 구성은 팀 공통 규격 기준. 현재 실제 인증 API로 동작한다 ("예시 데이터" 배지는 화면 코드 리뷰 때 정리). 지금은 프로필 이미지 설정만 제공한다.

| 항목 | 타입 | 범위 | 입력 위치 |
| --- | --- | --- | --- |
| 프로필 이미지 | 파일 | JPG·PNG, 4MB 이하, 실제 파일 내용까지 확인 | `/mypage` |

결과: 고른 이미지를 미리 보여 주고, 저장하면 마이페이지에 반영된다. 이미지가 없으면 닉네임(없으면 아이디) 첫 글자로 표시한다. 규칙에 맞지 않으면 선택을 취소하고 입력칸 아래에 안내한다.

## 프로필 수정 (`/mypage/edit`)

모델 화면은 아니다. 로그인 필요(`RequireAuth`). 경로는 Figma "프로필 수정 · 기본 정보", 화면 구성은 팀 공통 규격 기준. 현재 실제 인증 API로 동작한다. 지금은 닉네임만 수정한다 (Figma의 이름·생년월일·휴대폰번호·이메일 수정은 P2).

| 항목 | 타입 | 범위 | 입력 위치 |
| --- | --- | --- | --- |
| 닉네임 | 문자열 | 앞뒤 공백 제외 2~20자, 다국어 글자·숫자·기호 허용, 보이지 않는 문자 불가, 중복 허용 | `/mypage/edit` |
| 로그인 아이디 | 표시 전용 | 바꿀 수 없음 | `/mypage/edit` |

결과: 저장하면 마이페이지로 돌아가고, 바뀐 닉네임이 프로필 이미지 대체 글자에 반영된다.

## 미결정 사항

- 서비스별 입력 항목·타입·범위
- 실제 조회와 상태 화면의 연결
- 실제 빈 결과의 조건 변경 동작
- 실제 조회 재시도 함수
- 실제 결과의 예시 표시·마스킹 적용 위치
- 회원가입: 비밀번호 확인 칸, 안내 문구, 다국어 (나중에 추가)
- 프로필 이미지: JPG 자동 변환(`prepareProfileImage`), 이미지 삭제
- 회원가입에서 `next` 이어받기 (로그인 → 회원가입 → 로그인 후 원래 화면으로)
- 추천 서빙 방식 (Python 서버 / Spring에서 가중치로 직접 계산)
- 비교 라벨을 판정할 사람과 필요한 쌍의 수
- 용도 목록, 희망 금액 단위·범위, 체류기간·월소득 구간 경계, 적합도 점수 범위
- 보험 나이 입력 형식 (숫자 / 연령대)
- 전세보증금반환보증의 외국인 가능 여부 (HUG 공식 확인)
- 계좌 기준표의 비교 기간 규칙, 가입 지역 제한, 금융기관 구분
- 복리 주기 (금융상품한눈에에 없음, 월복리로 가정)
- 기간 일치 피처의 계산식
- 남은 체류기간 추정 방법 (MDIS는 지난 체류기간만 있음)
- 대출·보험의 외국인 가입 조건 출처
- 펼친 질문을 필수로 두면서 `모름`을 허용하는 방식
- 방문을 원치 않을 때의 필터·점수 처리 방식
- 팀 ERD v2 컬럼과 정제 항목의 대응

- 카드 이름·설명·이동 주소는 routeConfig.js를 사용한다.
- 카드 디자인은 홈의 배경색·아이콘 영역·모서리·버튼 규격을 재사용한다.
- 기본 배치는 2열이며, 기존 홈의 작은 화면 배치 규칙을 따른다.
- 사용자는 카드의 연결 버튼을 눌러 세부 기능 화면으로 이동한다.
- 모델 입력·출력·판단 근거와의 관계는 미정이다.

## 계산기 공통 기준

- 월 상환액: `/service/monthlyPayment`
- 총 이자: `/service/totalInterest`
- 두 화면은 공통 계산 함수와 LoanCalculator 컴포넌트를 사용한다.
- 상환 방식은 입력 영역 맨 위에서 선택한다.
- 순서는 만기 일시·원리금 균등·원금 균등이며 기본값은 만기 일시다.
- 대출 기간은 거치 기간을 포함한 전체 기간이다.
- 전체 기간은 1~600개월이며 거치 기간은 전체 기간보다 짧아야 한다.
- 대출 금액은 만원 단위 정수, 연 금리는 0~20%에서 소수 한 자리까지 허용한다.
- 대출 금액은 0보다 커야 하며 기존 입력 상한을 유지한다.
- 이자는 회차 시작 잔금에 연 금리÷12를 적용하고 원 미만을 버린다.
- 마지막 회차에는 남은 원금을 정산하여 잔금을 0원으로 만든다.
- 정수 계산으로 마지막 회차의 납입액은 기준 납입액과 조금 달라질 수 있다.
- 결과 영역에는 방식 이름과 설명을 표시하며 방식 선택 버튼은 두지 않는다.
- 계산 전에는 결과·그래프·상환표를 표시하지 않는다.
- 그래프는 월별 상환금 하나만 선으로 표시한다.
- 그래프 좌표는 만원 단위이며 표와 툴팁은 정확한 원 단위 금액을 표시한다.
- 기존 입력 설명과 결과 아래 계산 기준 설명은 제거한다.
- 실제 일수·납부일·수수료를 반영하는 계산은 적용하지 않는다.

### 월 상환액 계산기

- 입력: 상환 방식, 대출 금액, 연 금리, 대출 기간, 거치 기간.
- 만기 일시에서는 거치 입력을 숨기고 0개월로 계산한다.
- 분할상환은 거치 동안 이자만 납부하고 남은 회차에 원금을 상환한다.
- 결과 순서: 첫 회차 상환 금액, 평균 상환 금액, 최대 상환 금액, 총 상환 금액.
- 평균은 전체 대출 기간 기준이며 원 미만을 버린다.
- 표 순서: 회차, 상환금, 납입 원금, 이자, 납입 원금 합계, 잔금.

### 총 이자 계산기

- 입력: 상환 방식, 대출 금액, 연 금리, 대출 기간.
- 모든 방식에서 거치 없이 계산하며 설명에서도 거치 문장을 제외한다.
- 만기 일시·원리금 균등: 매월 상환 금액, 총 상환 금액, 총 이자 금액.
- 원금 균등: 첫 달 상환 금액, 총 상환 금액, 총 이자 금액.
- 만기 일시의 매월 상환 금액은 월 이자이며 원금은 마지막 회차에 납부한다.
- 표 순서: 회차, 원금, 이자, 총 금액.
