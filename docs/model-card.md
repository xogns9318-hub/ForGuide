# 모델 카드

## 한 줄 요약

금융상품 추천(계좌 / 보험 / 대출): 자격 규칙으로 거른 상품을 적합도 점수로 정렬하고, 점수에 기여한 항목을 근거로 보여 준다.

모델: 쌍대 비교 라벨로 가중치를 학습하는 LogisticRegression. 기준선은 규칙 가중합 점수다. 세 상품군이 같은 엔진(`ai/recommend/engine.py`)을 쓰고, 상품군마다 피처·필터·가중치만 다르다.

공통 상태 화면 초안:
로딩·빈 결과·실패·재시도·입력 검증·예시 표시·마스킹.

커뮤니티 목록 UI 초안:
서버와 로그인 연결 전에는 예시 게시글을 보여 주며, 모델을 사용하지 않는다.

## 문제 유형

추천. 1단계 자격 규칙 필터, 2단계 적합도 점수 순위. 실제 가입·승인 기록이 없으므로 승인 확률은 출력하지 않는다.

| 상품군 | 화면 | 상품 데이터 | 상태 |
| --- | --- | --- | --- |
| 계좌 (예·적금) | `/service/account` | 금융상품한눈에 정기예금·적금 | 기준선, 사람 판정 101쌍, 학습 완료 |
| 보험 (실손) | `/service/insurance` | 실손보험정보 API | 기준선 |
| 대출 | `/service/loan` | 금융상품한눈에 개인신용·전세자금대출 | 단순 버전 기준선 |

- 카드(신용·체크)와 입출금통장은 추천하지 않는다. 입출금통장은 계좌 관문 뒤 고정 안내로 다룬다.
- 모드: fast(필수 질문만, 지금 개발)와 plus(`더 정확한 추천`으로 펼친 질문까지, 가채점만). 모드는 답변 수로 판정하고 백엔드에서 다시 검증한다.

- 직업·병력·국적은 받지 않는다.

## 상품군별 기준

모든 상품군은 자격 판정을 **부합 / 확인 필요 / 불일치(흐림)** 로 나누고, 같은 그룹 안에서만 점수로 정렬한다. 계산하지 못한 조건은 충족으로 보지 않고 확인 필요로 둔다. 점수가 같으면 금리(보험은 보험료) 순이다.

### 계좌 (예·적금)

```
본인 명의 통장이 있나요?  아니오 → 첫 통장 안내(서류, 개설 순서, 한도제한계좌, 급여·공과금 연결)
                         예     → 예·적금 비교
```

**자격 판정**

| 조건 | 판정 |
| --- | --- |
| 가입대상에 내국인만 명시, 또는 보정 표에서 불가 | 불일치 |
| 방문 원치 않음 + 영업점에서만 가입 | 불일치 |
| 저축 기간 > 남은 체류기간 (plus) | 불일치 |
| 외국인 언급 없음("실명의 개인", "제한없음" 등), 보정 표에서 확인 필요 | 확인 필요 |
| 거주 외국인 가입 가능 명시 | 부합 |

- 공시에 없는 외국인 가입 정보는 전처리의 보정 표(`FOREIGNER_OVERRIDES`)가 우선한다. 출처와 확인일은 to-verify에 둔다.
- 영업점 전용 + 상품명에 지역이 있는 상품은 fast에서 확인 필요 그룹 맨 아래에 두고 가입 지점을 표시한다. plus에서는 거주 시·도가 다르면 불일치다.

**점수 (기준선)**

```
점수 = 0.5×금리점수 − 0.3×확인 필요 − 0.2×방문 필요 − 0.1×저축은행 − 0.2×비선호 금융기관
```

- 금리점수: 기본 금리를 단리·복리(월복리 가정)에 맞춰 연 환산 실제 수익률로 바꾸고, 그룹 최고보다 1%p 낮으면 0점이 되게 자른다. 우대금리는 정밀 추천(P2)에서 다룬다.
- 금리 이상값(같은 목적·기간에서 `Q3 + 1.5×IQR` 초과)은 그룹 최고 금리를 잡을 때 빼고, 상품은 "가입 조건 확인" 사유와 함께 확인 필요 그룹 맨 아래에 둔다. 특별한 가입 조건(출산, 첫 거래 등)이 붙은 경우가 많아서다.
- 비교 기간: fast는 사용자가 고른 기간, plus는 그 기간과 남은 체류기간 중 짧은 쪽 안에서 가장 긴 기간이다.
- 저축은행 감점은 모든 사용자에게 적용한다. 외국인이 급여·송금을 하는 주거래 은행에 예·적금을 두는 경향을 반영한 것이다. 은행 선호라고 답하면 감점이 더해진다. 빼지는 않는다.
- 예금자보호는 저축은행에도 적용되므로 결과 화면에서 저축은행을 덜 안전한 것처럼 표현하지 않는다.
- 가중치는 예시값이며 아래 학습 결과와 비교한다.

**학습 결과 (2026-10-23, 판정자 1명)**

| | 평가용 35쌍 정확도 | 5겹 교차 검증 | 방문 필요 | 저축은행 | 비선호 금융기관 |
| --- | --- | --- | --- | --- | --- |
| 기준선 | 0.543 | 0.583 | 금리 0.40%p | 0.20%p | 0.40%p |
| 학습 (`HUMAN_WEIGHT` 5) | 0.943 | 0.960 | 0.18%p | 0.45%p | 0.31%p |

- 판정 기준은 "은행 우선, 같은 종류끼리는 이자가 많은 쪽, 이자가 같으면 방문 없는 쪽"이었다.
- 판정자가 한 명이라 채택 여부는 미정이다.

### 보험 (실손)

```
건강보험에 가입돼 있나요?  예 → 실손 비교 / 아니오·모름 → 상담 탭
```

- 정렬 원칙: "같은 보장 중에서, 가입하기 편한 곳 가운데 보험료가 낮은 순".
- 5세대 실손은 모든 보험사의 담보 구성이 같아 보험료로 비교한다. fast는 기본형 + 특약1 + 특약2 합계로 비교한다.
- 비교 대상은 일반형이다. 노후·유병력자형은 따로 표시한다. MG손보(4세대)는 제외한다.
- 외국인 가입은 기본값이 확인 필요다(보험사별 추가 심사).
- 다이렉트 상품에 자동 가점은 없다. plus에서 온라인 가입 선호가 "예"일 때만 앞에 두고 본인 명의 휴대폰 인증을 안내한다.
- 추천하지 않는 보험: 상황별 보험(체류보험, 진단비, 운전자 등)은 고정 안내, 의무 보험(귀국비용·출국만기 등)은 다른 탭.

### 대출 (단순 버전)

- 금융상품한눈에 개인신용대출(카드론 제외)과 전세자금대출. 용도: 생활비·기타 → 신용대출, 주거(전세) → 전세자금대출.
- 공시에 외국인 조건과 한도가 없어 모든 상품을 확인 필요로 둔다. 사유: 외국인 가입 조건 미기재, 한도는 심사 후 결정.
- 점수는 평균 금리(낮을수록 좋음)와 확인 필요·방문 필요다. 금리점수는 그룹 최저보다 3%p 높으면 0점이다(임시값).
- 한도 충분도, 총 상환 비용, 상환 부담(월 상환액 ÷ 월소득)은 plus용 피처로 남겨 둔다.

## 출력 (y)

계좌 fast 확정 (2026-10-23). 보험·대출도 같은 틀을 쓴다.

| 항목 | 타입 | 예시 | 표시 위치 |
| --- | --- | --- | --- |
| 그룹 | 부합 / 확인 필요 순, 그룹마다 전체 상품 수·금융사 수와 상위 5개 (금융사당 대표 상품 1개, 나머지는 "이 금융사 상품 n개 더") | 확인 필요 336개, 93개사 | 추천 결과 |
| 불일치 | 전체 개수와 상위 3개, 불일치 사유 | 내국인만 가입 | 추천 결과 (흐림) |
| 순위 | 그룹 안 순위 | 1 | 상품 카드 |
| 상품 | 금융사, 상품명, 은행/저축은행, 저축 기간, 기본 금리·단리/복리, 실제 수익률, 가입 방법, 방문 필요 | 고려저축은행 정기예금, 4.02% | 상품 카드 |
| 추천 근거 | 문구 키 최대 3개: `high_rate`, `no_visit`, `bank` | `["high_rate", "no_visit"]` | 상품 카드 |
| 확인 필요·불일치 사유 | 문구 키 목록 | `foreigner_unspecified`, `domestic_only` | 상품 카드 |
| 가입 지역, 금리 이상값 | 있을 때만 | 진주, 통영 | 상품 카드 |
| 다음 행동 | 금융사 홈페이지·대표 전화, 그룹 안내 키(부합 `join_at_company`, 확인 필요 `ask_foreigner_eligibility`) | 1877-9900 | 상품 카드 |
| 고정 안내 | `rate_may_change`, `savings_bank_protected`, `reference_only` | 금리는 바뀔 수 있음 | 결과 하단 |
| 공시 기준월 | YYYYMM | 202609 | 결과 하단 |

- 결과에는 문구 키만 담고, 화면 문구는 `frontend/src/i18n/locales/ko.js`의 `recommendResult`에 둔다(그룹·근거·사유·다음 행동·안내).
- 점수는 그룹 안에서만 의미가 있는 상대값이라 화면에 보여 주지 않고 정렬에만 쓴다.
- 예시 이자는 보여 주지 않는다. 금액을 묻는 plus에서 다룬다.

## 결과 근거

점수 기여도(`가중치 × 피처값`)가 큰 피처 2~3개를 정해진 문구 템플릿으로, 사이트 언어로 보여 준다. 요청마다 LLM으로 설명을 만들지 않는다.

## 모델과 학습 방법

- 정답 데이터가 없으므로 "이 사용자에게 A와 B 중 어느 쪽이 나은가"를 사람이 판정한다(쌍대 비교). 입력은 피처 차이 `A − B`, 절편 없는 LogisticRegression의 계수가 곧 가중치다.
- 라벨은 섞어서 만든다. 한쪽이 모든 피처에서 같거나 나은 쌍은 자동 라벨(방향 학습), 장단점이 갈리는 쌍은 사람 판정(크기 학습)이다. 사람 판정 쌍의 일부는 평가용으로 뗀다.
- 가상 사용자: MDIS 2025 외국인 응답자에서 가중 추출한 60명(체류자격마다 최소 5명). MDIS에 없는 답은 고르게 무작위로 붙인다.
- 판정은 판정자별로 `ai/recommend/account/labels.json`에 "상황 + 두 상품" 내용 키로 저장해 쌍을 다시 만들어도 유지된다. 판정 페이지는 `judge_page.py`, 학습·가중치 저장은 `train.py`, 실험은 `ai/recommend/experiments.ipynb`.
- 서비스는 오프라인에서 학습한 가중치로 상품마다 점수를 한 번씩 계산해 정렬한다. 요청 중에 학습하거나 공공 API를 부르지 않는다.
- 쓰지 않는 모델: 신경망·트리 모델(데이터가 적고 추천별 근거가 약함), 승인 확률 모델(근거 데이터 없음). 라이브러리는 `ai/requirements.txt`.

| 외국인 가입·선호 근거 | 금융사 공식 안내, 업계 기사 | 출처·확인일은 to-verify |
| 건강보험 가입 대상 (상담 탭 참고) | 국민건강보험법 제109조 등 | 추천 모델에는 쓰지 않음 |

| 이후 | '이 상품으로 결정하기' 이동 기록 | 실제 선택 데이터 |

## API 초안

계좌 fast (Python): `ai/recommend/account/recommend.py`의 `recommend(user)`

- 입력: `purpose`(예금 / 적금), `term`(6 / 12 / 24), `visit`(상관없음 / 원치 않음), `institution`(은행 선호 / 상관없음). 값이 틀리면 `ValueError`로 항목별 허용값을 돌려준다.
- 출력: 위 "출력" 표의 JSON (`mode`, `input`, `base_month`, `weights`, `groups`, `mismatch`, `notices`).
- 가중치는 `ai/models/account_fast_weights.json`(`train.py`가 만듦)이 있으면 학습값, 없으면 기준선을 쓴다.
- HTTP 주소와 서빙 방식은 미정이다.

커뮤니티 예시 게시글 조회는 화면 확인용이며, 실제 게시글 조회 API는 미정이다.

## 공통 상태 화면

헤더·푸터 없이 공통 배경의 중앙에 아이콘과 문구를 표시한다.

- 로딩: 회전하는 모래시계와 대기 문구
- 빈 결과: 빈 목록 안내
- 실패·재시도: X 표시, 실패 안내와 재시도 버튼
- 입력 검증: 입력 항목 아래 오류 표시
- 예시 표시: 예시 데이터·예시값 배지
- 마스킹: 가상 이름·계좌번호를 일부 가려 표시
- 잘못된 접근: X 표시와 오류 문구

입력 검증 화면은 필수 입력을 확인하는 표시 초안이다.
실제 서비스 입력 항목과 검증 범위는 미정이다.

## 회원가입 화면 (`/signup`)

모델 화면은 아니며, 인증 흐름의 첫 화면이다. 경로·입력 항목은 Figma "회원가입 · 입력", 화면 구성은 팀 공통 규격(Banner + panel + form-grid) 기준. 현재 실제 인증 API로 동작한다 ("예시 데이터" 배지는 화면 코드 리뷰 때 정리).

| 항목     | 타입   | 범위                                                       | 입력 위치 |
| -------- | ------ | ---------------------------------------------------------- | --------- |
| 아이디   | 문자열 | 4~20자, 영문 소문자·숫자, 입력칸을 벗어나면 자동 중복 확인 | `/signup` |
| 비밀번호 | 문자열 | 8~32자, 소문자·대문자·숫자·특수문자 모두 포함, 보기 버튼   | `/signup` |
| 이름     | 문자열 | 1~50자, 문자 종류 제한 없음                                | `/signup` |
| 이메일   | 문자열 | 이메일 형식, 중복 불가                                     | `/signup` |

결과: 가입 성공 시 로그인 화면(`/login`)으로 이동한다. 입력 오류·중복은 해당 입력칸 아래에, 네트워크 등 그 밖의 실패는 폼 아래에 표시한다.

## 로그인 화면 (`/login?next=`)

모델 화면은 아니다. 경로·입력 항목은 Figma "로그인 · 마이페이지로 이동", 화면 구성은 팀 공통 규격 기준. 현재 실제 인증 API로 동작한다 ("예시 데이터" 배지는 화면 코드 리뷰 때 정리).

| 항목     | 타입   | 범위                                                         | 입력 위치 |
| -------- | ------ | ------------------------------------------------------------ | --------- |
| 아이디   | 문자열 | 빈 값만 확인 (가입 규칙을 드러내지 않음)                     | `/login`  |
| 비밀번호 | 문자열 | 빈 값만 확인, 보기 버튼                                      | `/login`  |
| next     | 쿼리   | 내부 경로만 허용, 외부 주소·로그인·회원가입 화면이면 홈(`/`) | 주소      |

결과: 성공하면 `next` 화면(없으면 홈)으로 이동한다. 실패하면 아이디·비밀번호 중 무엇이 틀렸는지 구분하지 않고 안내하며 비밀번호 칸을 비운다. 회원가입 직후에는 가입한 아이디를 미리 채운다. 이미 로그인한 상태로 들어오면 바로 `next`로 이동한다.

회원 전용 화면(`/mypage`, `/mypage/edit`)은 `RequireAuth`로 감싼다. 로그인 복원 중에는 확인 중 안내를 보여 주고, 로그인하지 않았으면 `/login?next=원래주소`로 보낸다. 화면 보호일 뿐이며 회원 정보는 서버가 토큰으로 다시 확인한다.

## 마이페이지 (`/mypage`)

모델 화면은 아니다. 로그인 필요(`RequireAuth`). 화면 구성은 팀 공통 규격 기준. 현재 실제 인증 API로 동작한다 ("예시 데이터" 배지는 화면 코드 리뷰 때 정리). 지금은 프로필 이미지 설정만 제공한다.

| 항목          | 타입 | 범위                                       | 입력 위치 |
| ------------- | ---- | ------------------------------------------ | --------- |
| 프로필 이미지 | 파일 | JPG·PNG, 4MB 이하, 실제 파일 내용까지 확인 | `/mypage` |

결과: 고른 이미지를 미리 보여 주고, 저장하면 마이페이지에 반영된다. 이미지가 없으면 닉네임(없으면 아이디) 첫 글자로 표시한다. 규칙에 맞지 않으면 선택을 취소하고 입력칸 아래에 안내한다.

## 프로필 수정 (`/mypage/edit`)

모델 화면은 아니다. 로그인 필요(`RequireAuth`). 경로는 Figma "프로필 수정 · 기본 정보", 화면 구성은 팀 공통 규격 기준. 현재 실제 인증 API로 동작한다. 지금은 닉네임만 수정한다 (Figma의 이름·생년월일·휴대폰번호·이메일 수정은 P2).

| 항목          | 타입      | 범위                                                                                | 입력 위치      |
| ------------- | --------- | ----------------------------------------------------------------------------------- | -------------- |
| 닉네임        | 문자열    | 앞뒤 공백 제외 2~20자, 다국어 글자·숫자·기호 허용, 보이지 않는 문자 불가, 중복 허용 | `/mypage/edit` |
| 로그인 아이디 | 표시 전용 | 바꿀 수 없음                                                                        | `/mypage/edit` |

결과: 저장하면 마이페이지로 돌아가고, 바뀐 닉네임이 프로필 이미지 대체 글자에 반영된다.

## 미결정 사항

### 일자리 목록 (`/service/jobListings`)

- 모델을 사용하지 않는 기관 안내 화면이다.
- 외국인 공공 취업 지원, 외국인 근로자 채용 정보, 외국인 유학생 취업 지원은 전국 단위 안내 카드로 표시한다. 목록 카드는 기관명·한 줄 설명·이용 대상·지원 언어만 요약해 비교한다.
- 지역 외국인 취업·상담 지원 구역에만 자체 드롭다운 지역 선택 UI를 두며, 선택지는 출처가 확인된 17개 시·도다. 선택한 지역의 기관 카드만 표시한다.
- 외부 공식 사이트는 새 탭으로 연결한다. 기관 상세 모달에는 카드와 중복되지 않는 이용 상황·이용 전 확인·출처·확인일을 표시한다. 다국어 번역은 추후 단계다.

### 취업 준비자료 이력서 (`/service/employment`)

- 모델을 사용하지 않는 입력 화면이다.
- 기본 이력서는 사진, 성명, 생년월일, 연락처, 이메일, 주소와 학력·경력·자격증·수상내역을 제공한다.
- 블라인드 채용 이력서는 사진·이름·생년월일을 제외하고 접수번호, 지원 직무, 연락처, 이메일, 경력·자격증·직무 관련 교육을 제공한다.
- 학력·경력·자격증·수상내역·직무 관련 교육은 각각 최대 4행이다.
- 현재 확정된 범위는 양식 UI와 탭 전환이다. mock 저장·불러오기, 인쇄·출력, 한국어 변환은 다음 단계에서 연결한다.

- 서비스별 입력 항목·타입·범위
- 실제 조회와 상태 화면의 연결
- 실제 빈 결과의 조건 변경 동작
- 실제 조회 재시도 함수
- 실제 결과의 예시 표시·마스킹 적용 위치
- 회원가입: 비밀번호 확인 칸, 안내 문구, 다국어 (나중에 추가)
- 프로필 이미지: JPG 자동 변환(`prepareProfileImage`), 이미지 삭제
- 회원가입에서 `next` 이어받기 (로그인 → 회원가입 → 로그인 후 원래 화면으로)
- 추천 서빙 방식 (Python 서버 / Spring에서 가중치로 직접 계산)
- 계좌: 학습 가중치 채택 여부(판정자 2명 이상 확인 후), 금융기관 선호 질문 유지 여부, 인터넷은행(카카오·케이·토스) 외국인 예·적금 처리, 금리 이상값 상품의 가입 조건 표시
- 보험: 나이 입력 형식(숫자 / 연령대), 노후·유병력자형 표시 방식, 보험료 점수 기준
- 대출: 용도 목록, 희망 금액 단위·범위, 금리점수 기준, 외국인 대출 조건 출처(전세 보증기관 포함)
- plus: 남은 체류기간·월소득 구간 경계, 기간 일치 피처, 펼친 질문의 `모름` 처리
- 적합도 점수 범위, 팀 ERD v2 컬럼과 정제 항목의 대응

## 주 기능 안내 화면

- 주 기능 배너 아래에 해당 기능의 세부 기능 카드를 표시한다.
- 카드 이름·설명·이동 주소는 routeConfig.js를 사용한다.
- 카드 디자인은 홈의 배경색·아이콘 영역·모서리·버튼 규격을 재사용한다.
- 기본 배치는 2열이며, 기존 홈의 작은 화면 배치 규칙을 따른다.
- 사용자는 카드의 연결 버튼을 눌러 세부 기능 화면으로 이동한다.
- 모델 입력·출력·판단 근거와의 관계는 미정이다.

## 계산기 공통 기준

- 월 상환액: `/service/monthlyPayment`
- 총 이자: `/service/totalInterest`
- 두 화면은 공통 계산 함수와 LoanCalculator 컴포넌트를 사용한다.
- 상환 방식은 입력 영역 맨 위에서 선택한다.
- 순서는 만기 일시·원리금 균등·원금 균등이며 기본값은 만기 일시다.
- 대출 기간은 거치 기간을 포함한 전체 기간이다.
- 전체 기간은 1~600개월이며 거치 기간은 전체 기간보다 짧아야 한다.
- 대출 금액은 만원 단위 정수, 연 금리는 0~20%에서 소수 한 자리까지 허용한다.
- 대출 금액은 0보다 커야 하며 기존 입력 상한을 유지한다.
- 이자는 회차 시작 잔금에 연 금리÷12를 적용하고 원 미만을 버린다.
- 마지막 회차에는 남은 원금을 정산하여 잔금을 0원으로 만든다.
- 정수 계산으로 마지막 회차의 납입액은 기준 납입액과 조금 달라질 수 있다.
- 결과 영역에는 방식 이름과 설명을 표시하며 방식 선택 버튼은 두지 않는다.
- 계산 전에는 결과·그래프·상환표를 표시하지 않는다.
- 그래프는 월별 상환금 하나만 선으로 표시한다.
- 그래프 좌표는 만원 단위이며 표와 툴팁은 정확한 원 단위 금액을 표시한다.
- 기존 입력 설명과 결과 아래 계산 기준 설명은 제거한다.
- 실제 일수·납부일·수수료를 반영하는 계산은 적용하지 않는다.

### 월 상환액 계산기

- 입력: 상환 방식, 대출 금액, 연 금리, 대출 기간, 거치 기간.
- 만기 일시에서는 거치 입력을 숨기고 0개월로 계산한다.
- 분할상환은 거치 동안 이자만 납부하고 남은 회차에 원금을 상환한다.
- 결과 순서: 첫 회차 상환 금액, 평균 상환 금액, 최대 상환 금액, 총 상환 금액.
- 평균은 전체 대출 기간 기준이며 원 미만을 버린다.
- 표 순서: 회차, 상환금, 납입 원금, 이자, 납입 원금 합계, 잔금.

### 총 이자 계산기

- 입력: 상환 방식, 대출 금액, 연 금리, 대출 기간.
- 모든 방식에서 거치 없이 계산하며 설명에서도 거치 문장을 제외한다.
- 만기 일시·원리금 균등: 매월 상환 금액, 총 상환 금액, 총 이자 금액.
- 원금 균등: 첫 달 상환 금액, 총 상환 금액, 총 이자 금액.
- 만기 일시의 매월 상환 금액은 월 이자이며 원금은 마지막 회차에 납부한다.
- 표 순서: 회차, 원금, 이자, 총 금액.

## 도움 기관 안내 — DB 기관 조회

- 경로: `/service/consultation`
- 기존 공통 헤더·푸터를 사용하며 서비스 화면의 배너는 표시하지 않는다.
- 최초 진입 시 전체 선택 목록과 DB에 등록된 기관 목록을 표시한다.
- 상담 분야·키워드·지역·언어·상담 방식의 기존 선택 목록을 유지한다.
- 검색어를 입력하거나 상담 분야와 키워드를 함께 선택하면 안내받기를 실행할 수 있다.
- 검색어는 최대 100자까지 입력한다.
- 검색어가 없을 때 상담 분야는 한 개, 키워드는 한 개 이상 선택한다.
- 상담 분야 변경 시 키워드를 초기화하고, 시·도 변경 시 시·군·구를 전체로 초기화한다.
- 검색어나 선택 조건을 변경하면 이전 선택 조건 확인 내용과 기관 결과를 즉시 숨긴다.
- 안내받기를 다시 누르면 확정한 조건으로 기관을 조회한다.
- 전체 기관 보기를 누르면 입력 조건을 초기화하고 전체 기관을 다시 조회한다.
- 직접 상담 여부, 선택 키워드 일치 개수, 미확인 조건 수, 기관 ID 순으로 정렬한다.
- 키워드 일치율은 지원 자격이나 승인 확률을 뜻하지 않는다.
- 기관 카드의 상세 보기에서 상담 업무별 운영정보와 공식 출처를 확인한다.
- 확인되지 않은 운영·언어·지역 정보는 ‘확인 필요’로 표시한다.
- 기관 조회의 로딩·오류·빈 결과 상태를 처리한다.
- 원본 지역 선택 목록과 최신 행정구역의 일치 여부는 미확인이다.
- 기호만 입력한 검색어는 잘못된 입력으로 안내한다.
- 기관 카드에도 등록된 언어별 시간대·전용 번호 조건을 표시한다.
- 상세 팝업의 내부 여백 클릭은 유지하고, 바깥 배경·닫기 버튼·Esc로 닫는다.

## 커뮤니티 댓글

- 댓글은 원댓글과 답글 한 단계까지만 작성할 수 있다.
- 답글 입력창은 대상 작성자의 `@닉네임`으로 시작하며, 작성자가 자유롭게 수정하거나 지울 수 있다.
- 원댓글과 답글 모두 로그인 회원별 공감 추가·취소를 지원한다.

## 헤더 — 가이드 메뉴

- 상단 메뉴는 가이드 소개·가이드 목록·문의하기로 구성한다.
- 상단 제목은 클릭으로 이동하지 않고, 마우스를 올리면 해당 목록을 펼친다.
- 펼친 메뉴의 배경은 사이트 전체 너비를 덮는다.
- 메뉴 뒤의 본문은 살짝 어둡게 표시하며 블러는 적용하지 않는다.
- 소개 목록과 각 가이드 이름, 문의 제목은 클릭할 수 없는 p 태그로 표시한다.
- 가이드 소개는 기존 주 기능 주소, 가이드 목록은 기존 세부 서비스 주소로 연결한다.
- 시뮬레이터·커뮤니티 소개는 `/categories/simulator`, `/categories/community`로 연결한다.
- 실제 서비스는 `/service/simulator`, `/service/community`로 연결한다.
- 내 문의·1:1 문의·자주하는 질문은 버튼만 표시하며 페이지는 연결하지 않는다.
- 메뉴 강조는 초록색 글씨와 글씨 아래에 간격을 둔 밑줄로 표시한다.
- 메뉴 밑줄은 가운데에서 양옆으로 펼쳐지고, 강조가 해제되면 가운데로 접힌다.

## 카테고리 소개 페이지와 배너

- 여섯 카테고리의 소개 페이지에 배너와 서비스 이동 카드를 표시한다.
- 시뮬레이터·커뮤니티 소개 페이지에는 각각 서비스 이동 카드 한 개를 표시한다.
- 서비스·회원 화면에서는 공통 배너를 표시하지 않는다.
- 홈 메인 배너의 최종 유지 여부는 미정이다.

## 제작 중 서비스 화면

- 적용 대상은 상담 준비 카드 만들기·대출 상품·보험 상품·계좌 개설·시뮬레이터다.
- 해당 서비스의 기존 제목·설명 패널 대신 제작 중 화면을 표시한다.
- 메인 영역 중앙에 새로 그린 정면 픽셀 오리를 표시한다.
- 오리는 고개를 들었다가 숙이는 동작을 반복한다.
- 문구는 "현재 페이지는 제작중입니다."와 "빠른 시일 내에 완성하겠습니다."로 표시한다.
- 일자리 찾기는 적용 대상에서 제외한다.
- 카테고리 소개 페이지의 배너와 이동 카드는 유지한다.
- 픽셀 오리는 흰색 몸과 주황색 부리·발로 표시한다.
