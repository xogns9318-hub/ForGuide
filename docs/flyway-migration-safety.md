# Flyway 마이그레이션 안전 규칙

## 이미 적용된 파일

- `V1`부터 현재 최신 버전까지의 파일은 이름과 내용을 수정하거나 삭제하지 않는다.
- 수정이 필요하면 다음 버전의 새 파일에 `ALTER TABLE` 또는 데이터 보정 SQL을 작성한다.
- 적용 여부는 `flyway_schema_history`의 `success = true`로만 확인한다.

## 새 파일 작성

- 파일명은 `V다음번호__설명.sql` 형식을 사용한다. 예: `V9__add_example_column.sql`
- 한 파일에는 하나의 목적만 둔다. 테이블 생성, 컬럼 추가, 인덱스 추가처럼 실패 범위를 작게 유지한다.
- MySQL의 DDL은 중간 실패 시 자동 롤백되지 않을 수 있으므로, 여러 테이블을 한 파일에 묶지 않는다.
- 이미 존재하는 테이블을 억지로 통과시키는 `IF NOT EXISTS`는 사용하지 않는다. 이는 환경별 스키마 차이를 숨긴다.

## 실패했을 때

1. 서버 재시작을 반복하지 말고 최초 오류 메시지와 실패 버전을 확인한다.
2. `flyway_schema_history`와 실제 테이블 구조를 읽기 전용으로 비교한다.
3. 반만 만들어진 변경은 팀 확인 후 되돌리거나, 이미 완성된 스키마라면 이력만 복구한다.
4. `flyway repair` 또는 이력 직접 수정은 공유 DB에서 반드시 대상 버전과 실제 구조를 확인한 뒤에만 한다.
